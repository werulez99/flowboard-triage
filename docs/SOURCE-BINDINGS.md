# Source-selected call bindings

`source-bindings-v1` is a provider wire format, not a new semantic policy. New production generations request it; compatible legacy paid responses and accepted policy-v9 guides remain readable/replayable without regeneration. No policy-version-only promotion occurs.

Each material callee invocation selects one entry record: caller/callee event IDs, current source ID/hash, exact occurrence ID and the claimed implementation source ID. Static candidates remain discovery candidates. The host never selects an implementation from the first matching name or ABI.

The compiler derives these mechanical fields from that selection:

- Original call span/quote and receiver expression spelling.
- Exact source identity, distinct from the broader analytical evidence note.
- Caller argument expression and parameter name/type for a selected parameter index at callee entry.
- Matching return dispatch/occurrence by reference to the same entering binding.

The model still supplies—and the substantive challenge must inspect—scenario/invocation choices, reachability, receiver proof, EVM context, argument meaning/units, symbolic constraints, later assignments, branch and failure continuation, state effects, report scope, expected rule, impact and counterevidence. Parser output does not establish these facts or create review attestations.

A reviewed quotation supplied through a complete enclosing file may also select one uniquely delimited function for native display. The original note ID, claim, quote and source identity remain unchanged; `nativeSources` is a derived presentation projection. Matching native function bounds and exact bytes are checked before materialization. Unread tails, declaration-only units, ambiguous boundaries and stale quotes are not promoted. An already supplied identical function keeps its canonical frame identity.

The challenge receives `earlierDraft` plus `assembledEarlier`: a compact keyed projection of compiled anchors, selected inputs and dispatch. Together these are the full assembled causal argument; semantic prose is not recopied into a second model. The ordinary schema, immutable evidence scopes, source/read coverage and semantic publication gate remain mandatory. Unknown/stale selectors fail explicitly. Later parameter values cannot reuse an entry selector to bypass an ordered assignment.

`bindingPlan` accompanies the canonical saved artifact. The gate recompiles and compares derived fields; publication digests cover the plan. Native cards keep the complete original function, use the derived visual occurrence and leave the claim-scoped evidence quotation untouched. Evidence navigation and Return remain local.

## Supported boundary

The current source-only input cannot authenticate observed external/proxy deployment identity. The outbound capability declaration and dispatch kinds now say so explicitly. A material deployed claim needs independently checked versioned observation through a supported intake; local quotes cannot masquerade as that observation. A complete source-conditional argument does not need an unrelated deployment prerequisite.

Existing bounded path/failure checks are unchanged: repeated calls, ordered boolean reassignment, local construction proofs and supported typed catch/return/rethrow are checked. Arbitrary modifiers, compound side effects, assembly, dynamic dispatch and unsupported paths are not silently treated as continuing. Exact syntax assembly is not a general symbolic executor.

Overall support does not imply agreement with every secondary report statement. Each supported claim needs established behavior, rule and impact; the overall supported result needs at least one such complete claim. A narrowed secondary impact may be refuted by checked counterevidence. Every claim still needs the full obligation set, current evidence and fresh review; unresolved material scope still blocks publication.

## Verification boundary

Production parser/acceptance/explanation-review/gate/exposure controls exercise positive and negative call paths. The five-function native fixture now sends selected-ID responses through the coordinator, stored review and original renderer. These are fixed responses and zero external model calls, not evidence of general live-model correctness.

The explicit developer evaluation guard in `scripts/finding-evaluation-guard.js` is outside editor navigation. It requires a frozen finding/snapshot and local reference preflight, permits only its declared generation/challenge sequence, and rejects a sibling, failed-generation continuation or extra invocation before coordinator reservation as well as transport dispatch. It supplements normal ownership, health, capacity and accounting; it does not increase ordinary production deadlines or allowances.
